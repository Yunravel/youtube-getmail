# 爬虫产出自动推送到大数据库

## 目标

爬虫跑完产出 Excel 后，自动上传到 kol-outreach 的导入接口，数据进大数据库。不再手动传文件。

## 架构

```
爬虫（本机，不动）
  ├─ crawl_excel.py  → 产出 .xlsx（邮箱采集结果格式）
  └─ KOL-Find 脚本链 → 产出 .xlsx（多平台候选池格式）
        ↓ 跑完后调用
  push_to_kol.py（新增，独立推送工具）
        ↓ HTTP POST（带 token）
  kol-outreach /api/kols/import-candidate（已部署）
        ↓
  大数据库 kol_candidate + 选入 kol
```

爬虫代码**完全不改**。推送是独立的工具脚本，爬虫跑完后手动/自动调用一次即可。

## 已确认决策
- 爬虫不动（本机环境复杂）
- 用 HTTP 推送到已部署的 import-candidate 接口
- 鉴权用 token（复用 Snov webhook 的 token 模式）

## 实施步骤

### 步骤 1：给导入接口加 token 鉴权
**修改** `backend/api/kol.py` 的 `import_candidate` 接口
- 加 `X-Import-Token` header 校验（复用 `settings.SNOV_WEBHOOK_TOKEN`，不必新增环境变量）
- 参照 webhook.py:294-296 的 `hmac.compare_digest` 模式
- 缺 token 或不匹配 → 401
- 前端页面上传时也要带 token（前端从新接口拿，或用固定 header）

### 步骤 2：新增推送工具
**新建** `backend/scripts/push_to_kol.py`
- 接收 xlsx 路径 + 格式（candidate/email-collection）
- 读环境变量：`KOL_API_URL`（https://kol.20020525.xyz）、`KOL_IMPORT_TOKEN`
- 自动判断格式（按 sheet 名/列名），调对应接口：
  - 含「全部候选」28列 → `/api/kols/import-candidate`
  - 三份邮箱采集格式 → 同接口（接口已能处理，或加 preset 参数）
- 失败重试 3 次，打印统计
- 独立可跑：`python push_to_kol.py xxx.xlsx`

### 步骤 3：配置与文档
- `.env.prod.example` 加 `KOL_IMPORT_TOKEN` 说明（实际值用现有 SNOV_WEBHOOK_TOKEN）
- 在爬虫项目根目录写个 `推送说明.md`：爬虫跑完后怎么调 push_to_kol.py
- 可选：爬虫项目加个 `推送.cmd` 一键脚本

## 不做（明确排除）
- 不改爬虫代码（crawl_excel.py / kol_*.mjs 不动）
- 不把爬虫搬到服务器（不可行，需浏览器+登录）
- 不做自动监听文件夹（爬虫跑完手动/脚本调一次推送即可）
- 不合并 git 仓库（两个项目保持独立，推送工具作为桥梁）

## 鉴权设计细节
- 接口校验 header `X-Import-Token`，值用 `hmac.compare_digest` 与 `settings.SNOV_WEBHOOK_TOKEN` 比对
- 复用现有 token 的理由：避免新增环境变量；该 token 已在 .env.prod 配置且足够随机
- 前端页面（运营手动上传）也要带 token——但前端 token 暴露在 JS 里不安全。**折中**：前端上传走"无 token 但限内网"、爬虫推送走"带 token 走公网"。或者前端调一个 `/api/auth/import-token` 拿一次性 token。

实际上更简单：**前端页面不加 token**（它通过 traefik 同源访问，且是运营内部工具），**只给爬虫推送的公网路径加 token**。但接口是同一个……所以两者都要 token。

**最终方案**：接口加 token，前端上传时从 cookie/已知值带 header，爬虫从环境变量带。token 值就是 SNOV_WEBHOOK_TOKEN（已在生产环境变量里）。

## 工作量
- 步骤 1（鉴权）：1 小时
- 步骤 2（推送工具）：1.5 小时
- 步骤 3（文档配置）：半小时
- 测试：1 小时
- **合计：半天**

## 验收标准
- 接口无 token → 401
- 接口带正确 token → 200，正常导入
- push_to_kol.py 能把本地 xlsx 推到生产并导入成功
- 前端页面上传仍能工作（带 token）
- 爬虫跑完后调 push_to_kol.py，数据自动进库

## 风险
| 风险 | 对策 |
|---|---|
| token 暴露在前端 JS | 内部工具可接受；后续可改 session 鉴权 |
| 推送时网络中断 | 重试 3 次 + 失败明确报错（爬虫产出仍在本地不丢）|
| 公网接口被扫 | token 校验 + traefik 限速（已有）|
