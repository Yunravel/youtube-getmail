# 本地 Docker 数据库对齐生产 —— 执行方案（版本 A）

## 目标
把手动 `docker run` 起的 `kol-local-db`（匿名卷）迁移成 **compose 托管 + 命名卷**，结构对齐 `docker-compose.prod.yml`，同时：
- 后端**不动**（继续宿主机 uvicorn + `localhost:5432` 连库，热重载保留）
- 现有数据（282 KOL + 34 thread + 35 message）**无损迁移**
- 不碰现有 `docker-compose.yml`（零回归）
- 不提交任何凭据

## 为什么这么设计
- 匿名卷是核心风险（删容器姿势错就丢全部数据，难备份难识别）
- compose 托管 = 一键启停 + 开机自启 + 配置即文档
- 不碰 `docker-compose.yml`（里面 backend 用 sqlite 的"配置谎言"原样保留，只在新文件顶部用注释标注已废弃，避免回归）

## 步骤 1：新建 `docker-compose.dev.yml`

路径：`D:\mail\kol-outreach\docker-compose.dev.yml`

内容要点（对齐 prod 的 db 服务结构）：
- service 名 `db`（与 prod 一致），container_name 保留 `kol-local-db`（后端 .env 不用改）
- 镜像 `postgres:16-alpine`（与 prod 完全一致）
- 命名卷 `kol-db-data`（对齐 prod 的 `db-data` 命名风格）
- 端口 `5432:5432`（暴露到宿主机，后端 localhost:5432 直连）
- 健康检查 `pg_isready -U kol`（对齐 prod）
- restart: `unless-stopped`（开机自启，对齐 prod）
- 环境：`POSTGRES_DB=kol_outreach`、`POSTGRES_USER=kol`、`POSTGRES_PASSWORD=local-dev-password`（保持现状，后端 .env 不用改）
- 顶部注释：明确这是 dev 专用、勿部署到生产、`docker-compose.yml` 里的 sqlite 配置已废弃
- **密码用 `${POSTGRES_PASSWORD:-local-dev-password}` 软默认**，允许将来用 `.env` 覆盖，但不硬性强迫你建 `.env`

## 步骤 2：数据无损迁移（匿名卷 → 命名卷）

这是最关键的一步，保证零丢失。策略：**先备份数据到宿主机 .sql 文件兜底，再迁移到命名卷，旧卷保留兜底**。

执行顺序：
1. **停止后端**（你手动停 uvicorn，避免迁移期间有写入）—— 我会提示你，不替你停
2. **停止旧容器**：`docker stop kol-local-db`（只停不删，数据还在匿名卷里）
3. **备份兜底**：用临时容器挂载匿名卷，`pg_dump` 导出全库到宿主机 `D:\mail\kol-outreach\backups\kol_outreach_YYYYMMDD.sql`（纯文本 SQL，最稳的兜底）
4. **创建命名卷**：`docker volume create kol-db-data`
5. **启动新 compose**：`docker compose -f docker-compose.dev.yml up -d`（会创建 `kol-local-db` 容器并挂载空命名卷 —— 但容器名被旧容器占用，所以这步前要先 `docker rm kol-local-db`，**只删容器不删卷** `-v` 绝不加）
6. **导入数据**：用临时容器把备份 SQL 灌进新容器（`psql -h ... -f backup.sql`）
7. **校验**：行数对账（KOL 应=282、thread=34、message=35、0 空邮箱、0 孤儿）
8. **旧匿名卷保留**：不立即删，命名卷跑稳几天后再清理（`docker volume rm 22a8c5...`）

关键安全点：
- 第 5 步 `docker rm kol-local-db` **绝不加 `-v`**（加 `-v` 会连匿名卷一起删 = 全部数据消失）
- 第 3 步先有 .sql 兜底，即使中途出错也能从 SQL 恢复
- 旧容器/旧卷全程保留到步骤 8 之后，不提前删

## 步骤 3：验证 + 收尾

- 重启后端（你手动），确认 uvicorn 能连上、`/health` 返回 200
- 查 `docker compose -f docker-compose.dev.yml ps` 确认健康检查通过
- 把 `backups/` 加入 `.gitignore`（避免备份 SQL 误提交，里面含数据）
- 写一份 `docs/LOCAL_DOCKER_DB.md`：记录 dev compose 用法、启停命令、数据迁移/备份流程
- README 里"本地开发"章节补一句：数据库用 `docker compose -f docker-compose.dev.yml up -d`

## 上传服务器要改什么
**什么都不用改。** 服务器跑 `docker-compose.prod.yml`（已正确），本地新增的 `docker-compose.dev.yml` 是 dev 专属，部署时根本不用它。本地改动对服务器透明。

## 风险与兜底
- 最大风险：`docker rm` 误加 `-v` 删掉匿名卷 → **兜底**：步骤 3 先 pg_dump 出 .sql，有备份在手
- 迁移期间后端短暂不可用 → 你手动控制停/启时间，挑不用的时候做
- 旧卷保留几天 → 命名卷跑稳后再清理，有回退余地
- `backend/.env` 含真实 Snov 凭据 → 已被 `.gitignore` 忽略，新文件不引用任何凭据（密码走环境变量软默认）
