# KOL 字段补全爬取方案

## 目标
对 860 个有邮箱的 KOL，按 HotLead 报价单列补全这些字段：**followers（粉丝数）、country（国家）、niche/position（社会身份/内容定位）**。覆盖全部 4 个平台（YouTube/Instagram/TikTok/X）。

## 数据现状（已审查）
| 字段 | 缺失 | 说明 |
|---|---|---|
| followers | 499/860 | 报价单 I 列，核心数据 |
| country | 504/860 | 区域筛选用 |
| niche | 61/860 | 报价单 F/G 列源头 |
| position | 849/860 | 报价单 F/G 列源头 |
| channel_url+profile_url 双空 | 36/860 | 这些需要先反查 |

## 实现路径

### 1. 新增文件 `backend/services/crawler/profile_parsers.py`（核心解析器）
为 IG/TikTok/X 写纯函数解析器（与 youtube.py 同风格，只解析、不抓网）：
- `parse_instagram(html) -> dict`：从 og:description meta（"X Followers, Y Following, Z Posts - ..."）抽粉丝数；从 title/description 推断 niche。
- `parse_tiktok(html) -> dict`：从 SIGI_STATE / __UNIVERSAL_DATA_FOR_REHYDRATION__ JSON 抽 followers；退回 og:description。
- `parse_x(html) -> dict`：从 og:description 抽 followers。
- 三个函数返回统一结构 `{followers, country, niche_hint, title, description}`，**全部基于正则/meta，平台改版只改这里**。
- YouTube 复用 `youtube.py` + `normalize.resolve_country` + `normalize.parse_subscriber_count`，不重写。

### 2. 新增文件 `backend/scripts/backfill_kol_fields.py`（CLI 入口）
镜像 `backfill_kol_profile.py` 的成熟模式（dry-run / commit / on_progress / 统计 dict）：

```
python -m scripts.backfill_kol_fields --platform youtube --limit 50        # 预览
python -m scripts.backfill_kol_fields --platform youtube --commit           # 写库
python -m scripts.backfill_kol_fields --platform instagram --commit         # 单平台
python -m scripts.backfill_kol_fields --commit                              # 全部
```

执行流程：
1. 按 platform 分批从 DB 取出 KOL（filter: followers IS NULL/0 OR country 空 OR niche 空）
2. **YouTube**：`HttpxFetcher().fetch_text(channel_url + "/about")` → 复用 youtube.py 解析 → 填 followers/country/niche
3. **IG/TikTok/X**：`PlaywrightFetcher().fetch_text(profile_url)` → 调对应解析器
4. 解析失败/被反爬 → 写入 `backfill_missed_{batch}.csv`（含 kol_id/name/platform/url/原因），不报错
5. 仅填空字段（不动人工已填值），用 gather_pool 限并发（YT 6，IG/TT/X 3）
6. niche 推断：能用现有 `ai_personalize.analyze_niche` 关键词规则就用，不再调 LLM（节省 token）

### 3. 不改动现有文件
- 不动 `pipeline.py / fetcher.py / youtube.py / normalize.py`，全部复用
- 不动 alembic 迁移（无 schema 变更）
- 不动前端/API（你说 CLI 跑就行）

## 关键风险与对策
| 风险 | 对策 |
|---|---|
| IG/TikTok 反爬重定向登录页 | Playwright 抓不到就进 missed.csv，不阻塞；预计成功率 30-60% |
| 本机无 chromium | 脚本启动时 `playwright install chromium` 自检并提示 |
| 36 个双空 URL 的 KOL | 用 email 域 + name 在 YouTube 搜反查；找不到的进 missed.csv |
| 平台大小写不一致（YouTube/youtube） | 写库时顺便 normalize 为 Title Case |

## 验收方式
1. dry-run 输出每条 KOL 将填入的字段值（before/after 对比）
2. commit 后跑 SQL 复查：`SELECT count(*) FILTER (WHERE followers IS NULL OR followers=0) FROM kol` —— 应从 499 显著下降
3. missed.csv 人工抽查，确认是反爬失败而非代码 bug
