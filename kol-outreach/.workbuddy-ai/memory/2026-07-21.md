### 教训
1. **本地数据排查要"全栈式"**：不只查 `.db` 文件、`.sqlite`，还要 `docker ps`、连 PG、Mongo、Redis 等容器。漏一个路径整个判断就错
2. **`\COPY FROM '/path'` 是容器内路径**：postgres 进程看不到宿主机文件系统，必须先 `docker cp` 进去（或用 stdin 流）
3. **`TRUNCATE ... RESTART IDENTITY` 同时清数据 + 重置序列**：迁移时常用，但要注意"先 TRUNCATE 再 COPY 同一张表"会丢失败回滚能力，更稳的是 `INSERT ... ON CONFLICT`
4. **Fernet key 同步 = 业务级强约束**：跨机器迁数据前必须先对齐 MASTER_KEY，否则密文就是垃圾。A 方案（统一 key）最简单但有"丢了全完"风险
5. **IMAP 应用代码全链路 = decrypt + login + fetch_recent + subject 归一化 + KOL 匹配 + DB 更新**：每一环都要验，单独 imaplib 验通不算 end-to-end
6. **应用代码 `sync_one_mailbox` 接受 `MailboxCredential` 对象**：可以直接传 ORM 实例，比 trigger_sync 端点更灵活（后者只能跑全部）
7. **SSH env vars 在多 bash 调用间不持久**：每个 Bash tool 调用都是新 shell，export 之后只对当前调用内有效。涉及多步操作要在**同一个** Bash 调用里 export + 跑命令
