## 一、这是什么

给 KOL 营销代理商(Richup Media)用的**外联中台**:

```
Snov.io 发信/收信(运营在 Snov 网页操作)
        │  webhook 实时推送 + 每 2 分钟 API 轮询兜底
        ▼
中台同步邮件会话 ──→ AI 意向分析(分级打分) ──→ Hot Lead 看板(运营跟进)
        │
        ├─ IMAP 直连发信邮箱:抓真附件 + 补录 Snov 拿不到的第三方地址回信
        ├─ 报价识别(正文/PDF/图片 OCR)→ 报价自动回复(默认关,总开关在看板)
        └─ 飞书多维表格"一达人一行"持久同步(指数退避重试 + 定时对账)
```

中台**不代发邮件**;运营始终回到 Snov 人工回复。

客户与名单:Dola(38 KOL)、Mango(194 KOL,分 Dreamina/Pippit/Kimi/Dola
四个列表);另有爬虫采集的 Hypic 等候选池(见 `output/` 下 xlsx)。

## 四、数据同步链路与消息来源标识

一条回信可能经三条通道进库,靠 `message.message_id` 前缀区分来源:

| message_id 前缀 | 来源 | 说明 |
|----|----|----|
| (Snov 原生 ID / `snov:inbound:` 指纹) | webhook 实时推送 | 字段最全,含 campaign 归属 |
| `snov:history:` | 每 2 分钟轮询 `/v1/get-emails-replies` | 兜底;无收件邮箱(unknown@snov.local,后由 IMAP 修复)、无附件 |
| `imap:` | IMAP 未匹配回信补录(7/26 新增) | Snov 拿不到的第三方地址真实回信 |

三条通道互相幂等:webhook 与轮询之间按"发件人+主题+正文+时间"内容比对去重;
IMAP 补录按 RFC Message-ID 去重。附件只有 IMAP 能拿到真文件,存
`/app/data/attachments/<message_id>/`(backend-data 卷)。

## 五、7/26 问题诊断:"部分邮件数据获取不到"的原因

基于 7/15–7/25 运行日志(约 3.7 万行)与数据库取证:

1. **Webhook 从未接通(根因)**。日志 0 条 webhook 请求,库内消息 100% 来自
   轮询(`snov:history:`),0 条 outbound——"已发送邮件"只有 webhook 能送。
   原因:中台此前只跑在无公网地址的工作站,Snov 侧从未登记订阅。
2. **第三方地址回信 Snov 不回传**。Snov 只把"prospect 登记邮箱发来的信"算作
   campaign 回复;经纪人代回(如 bossmgmtgrp.com)、Zendesk/Intercom 客服系统
   的真实回信,webhook 和轮询 API 都拿不到。IMAP 日志中 1.3 万+ 条
   "邮件无匹配 thread"里混着这类真回信,旧代码只记日志丢弃。
3. **轮询接口字段残缺**:无收件邮箱、无附件、无邮件 ID(靠内容指纹幂等)。
4. **指纹碰撞**:同一 KOL 两封内容完全相同的回信会被误判 duplicate 丢第二封。
5. **IMAP 代理链路瞬断**(SSL EOF),部分邮箱整轮同步失败(工作站代理问题,
   服务器直连基本不受影响)。
