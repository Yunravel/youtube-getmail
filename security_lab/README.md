# 模拟邮箱限流安全实验室

这是一个只绑定本机 `127.0.0.1` 的隔离靶场，用于授权测试 `/view-email` 的计数一致性和令牌安全。它不连接 YouTube 或其他第三方服务，邮箱均为 `.test` 模拟数据。

## 安全模型

- 每账号每日 20 次后返回模拟验证码挑战；
- 同时记录账号、IP、设备、会话四层计数；
- SQLite `BEGIN IMMEDIATE` 将额度检查和四层递增放在同一个原子事务中；
- 请求 ID 防重放；
- 验证码挑战与放行令牌随机生成、只保存 SHA-256、短期有效、单次使用；
- 挑战和放行令牌绑定账号、IP、设备和会话；
- 默认不信任 `X-Forwarded-For`，防止直接伪造来源 IP。

账号层是主限制。达到 20 次后，单纯轮换 IP、设备或会话仍不能直接读取邮箱。实验室的模拟验证码答案为 `LAB-OK`，仅用于验证合法挑战流程。

## 启动

```powershell
python -m security_lab.server --reset
```

服务地址：`http://127.0.0.1:8088`，模拟 Bearer Token：`lab-token-alice`。

## 自动化安全测试

```powershell
python -m unittest security_lab.tests -v
```

测试会尝试：

- 80 个并发请求争抢 20 次额度；
- 轮换 IP、设备和会话绕过账号限制；
- 重放请求 ID；
- 重放验证码挑战；
- 重放验证码放行令牌；
- 把放行令牌转移到另一会话；
- 使用无效身份令牌读取邮箱。

## k6 授权压力测试

先重置并启动服务，再在另一个终端运行：

```powershell
k6 run security_lab/k6_authorized.js
```

k6 使用 40 个虚拟用户并发发送 80 个请求。预期只有 20 个请求取得模拟邮箱，其余请求返回 `429 captcha_required`，且受限响应不得包含邮箱。

不要把脚本指向不属于你的系统；`BASE_URL` 只应设置为明确授权的测试环境。
