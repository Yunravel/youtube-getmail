# 授权安全测试报告

测试日期：2026-07-15  
范围：本仓库 `security_lab` 本地模拟服务，不包含任何真实第三方系统。

## 结果摘要

| 测试 | 结果 | 证据 |
|---|---|---|
| 80 个并发请求争抢账号 20 次额度 | 通过 | 20 成功、60 返回模拟验证码；账号计数为 20 |
| HTTP 连续 25 次请求 | 通过 | 20 成功、5 返回 `429` |
| 轮换 IP、设备、会话 | 未绕过 | 账号层仍返回模拟验证码 |
| 相同请求 ID 重放 | 已阻止 | 返回 `409 request_id_replayed`，计数未增加，响应无邮箱 |
| 验证码挑战重放 | 已阻止 | 返回 `409 challenge_replayed` |
| 验证码放行令牌重放 | 已阻止 | 返回 `403 replayed_grant` |
| 放行令牌跨会话转移 | 已阻止 | 返回 `403 grant_binding_mismatch` |
| 无效身份令牌 | 已阻止 | 返回 `401`，响应无邮箱 |

在测试覆盖的路径中，未能在不通过模拟验证码的情况下取得第 21 个邮箱。

## 设计保障

- 额度检查与账号/IP/设备/会话四层计数递增位于同一个 SQLite `BEGIN IMMEDIATE` 事务中；
- 验证码挑战和放行令牌均为短期、单次使用，并绑定四层身份；
- 数据库只保存挑战和放行令牌的 SHA-256；
- 受限和重放错误响应不包含邮箱；
- 服务默认只绑定 `127.0.0.1`，且不信任 `X-Forwarded-For`。

## 剩余风险与生产建议

1. 模拟 Bearer Token 是固定字符串，本质上可在账号剩余额度内被重放。生产环境应使用短期访问令牌，并考虑 DPoP/mTLS 或逐请求签名；所有传输必须使用 TLS。
2. 攻击者可制造大量验证码挑战和唯一请求 ID，造成数据库增长。生产环境应增加挑战签发速率限制、过期数据清理、表容量监控及存储配额。
3. `LAB-OK` 是故意公开的模拟验证码答案，只用于测试流程，不能替代真实验证码服务端校验。
4. SQLite 适合单机靶场；多实例生产部署应使用支持原子条件更新的共享存储，并执行跨实例并发测试。
